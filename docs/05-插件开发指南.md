# 05 · 插件开发指南

> 更新日期：2026-10-24
> 契约版本：**apiVersion 1.2**（`PluginManifest.ContractVersion`）｜插件次版本不高于宿主即可加载
> 配套：`01-插件系统设计.md`（内部设计）· `03-插件能力盘点与缺口.md`（能力边界）· `04-主题变量.md`（换肤契约）

---

## 1. 一分钟了解

插件往三个方向扩展启动器：

1. **改启动参数** —— 加 JVM 参数、游戏参数
2. **加界面** —— 侧栏一整页、设置里一块、工具栏按钮、启动层（动画 / 密码）
3. **用宿主的能力** —— 启动实例、装版本、把下载丢进队列

插件和宿主**同进程**，是普通 .NET 程序集。这不是沙箱：契约是"推荐路径"，不是安全边界。

---

## 2. 两种形态

| | Tier 1 声明式 | Tier 2 程序集 |
|---|---|---|
| 写什么 | 只有 `manifest.json` | `manifest.json` + 实现 `IPlugin` 的 C# |
| 能做的事 | 加参数、挂界面 | 全部 |
| 要不要编译 | 不要 | 要 |

## 3. 最小插件

### 3.1 目录结构

```
plugins/
  my.plugin/
    manifest.json
    MyPlugin.dll            （Tier 2 才需要）
    ui/
      page.html
      page.js
```

### 3.2 manifest.json

```json
{
  "schemaVersion": 1,
  "id": "my.plugin",
  "name": "我的插件",
  "version": "1.0.0",
  "type": "managed",
  "entry": "MyPlugin.dll",
  "entryType": "MyPlugin.Entry",
  "description": "一句话说明它是干什么的",
  "icon": "icon.png",
  "apiVersion": "1.1",
  "minHostVersion": "0.1.0",
  "permissions": ["ui:page"],
  "ui": [
    { "slot": "page", "html": "ui/page.html", "script": "ui/page.js", "title": "我的页面" }
  ]
}
```

`schemaVersion` 必须是 `1`，少了会直接 `invalid`（报"schemaVersion 必须是 1，现在是 0"）。

### 3.3 代码骨架

```csharp
using ML.Plugin.Abstractions;

public sealed class Entry : IPlugin, IPluginCommand
{
    private IPluginContext _context = null!;

    public Task InitializeAsync(IPluginContext context, CancellationToken ct)
    {
        _context = context;
        context.Log.Info("插件已加载");
        return Task.CompletedTask;
    }

    public Task ShutdownAsync(CancellationToken ct) => Task.CompletedTask;

    // 页面里的 MLPlugin.call('hello', {...}) 会走到这里
    public Task<string?> ExecuteAsync(string command, string? payload, CancellationToken ct)
        => Task.FromResult<string?>(command switch
        {
            "hello" => "{\"ok\":true,\"echo\":\"" + payload + "\"}",
            _ => "{\"ok\":false,\"error\":\"未知命令\"}"
        });
}
```

### 3.4 页面脚本

宿主只往脚本里传一个对象 `MLPlugin`：

```js
(function () {
  MLPlugin.call('hello', { a: 1 }).then((raw) => {
    const data = JSON.parse(raw);
    document.getElementById('out').textContent = raw;
  });

  MLPlugin.status('已就绪');        // 写到插件页状态栏
  MLPlugin.notice('提示', '正文');   // 弹一个信息框
  MLPlugin.dismissStartup();        // 只在 startup 层里用
})();
```

脚本是 `new Function('MLPlugin', 源码)` 执行的，**同上下文**——`document`、`window` 都能直接摸到（刻意不给参数，但拦不住）。

## 4. 能做什么

### 4.1 生命周期

| 能力 | 接口 | 约束 |
|---|---|---|
| 初始化 | `InitializeAsync(ctx, ct)` | 10 秒超时，超时禁用该插件 |
| 卸载 | `ShutdownAsync(ct)` | 3 秒超时，之后强制卸载 |
| 启动前加参数 | `ILaunchHook.OnBeforeLaunch(req)` | 只能追加，**不能否决** |
| 启动前拦截 | `ILaunchGuard.OnGuardLaunch(req)` | 返回 `HookResult.Deny("原因")` 可以拒绝 |
| 监听事件 | `IEventHook.OnHostEvent(name, json)` | 见 4.5 |
| 响应界面 | `IPluginCommand.ExecuteAsync(...)` | 页面调 C# 的唯一通道 |
| 自己的设置 | `IPluginSettings.Get/Set/All` | `plugin-data/<id>/settings.json` |
| 日志 | `IPluginLogger.Info/Warn/Error` | 宿主加前缀落盘 |

### 4.2 能读的状态

| 成员 | 内容 |
|---|---|
| `Host.GameRoot` | `.minecraft` 路径 |
| `Host.Instances` | Name / VersionId / Directory / GameDirectory / ModsDirectory / AccountName / **Running** |
| `Host.Versions` | Id / Type / Protocol（Protocol 目前恒为 null，见 §9） |
| `Host.CurrentAccount` | Name / Kind / Uuid（**没有令牌**） |
| `ctx.Directory` | 插件自己的目录（只读） |
| `ctx.DataDirectory` | `plugin-data/<id>/`（可写、升级不丢） |

### 4.3 能做的动作

| 成员 | 说明 |
|---|---|
| `Host.LaunchAsync(name, ct)` | 启动实例，失败返回原因不抛 |
| `Installer.ListRemoteAsync(includeSnapshots, ct)` | Mojang 官方清单 |
| `Installer.InstallAsync(versionId, progress, ct)` | 装版本，走下载队列 |
| `Downloads.Submit(title, files)` | 提交下载任务 → 出现在下载页 |
| `Downloads.WaitAsync(id, ct)` | 等完成 |
| `Downloads.Status(id)` | 字节数、文件数、错误 |
| `Host.AdoptProcess(pid)` | 托管自己起的子进程：启动器一退（含崩溃），它跟着死 |
| `Host.ServerRoot` | 建议的服务器目录（`data/servers/`，已创建；放不放这里随你） |

> `Installer` 是**便利层，不是唯一路径**：装版本的机制你完全能自己写。
> 宿主代劳是因为 natives 解压和 legacy 资源摊平这两个坑重写必错，而且报错要等到游戏启动才出现。
> 不想用这份便利也行，自己拼装即可。

### 4.4 界面插槽（5 个）

| 插槽 | 位置 | 需要 `ui:page` |
|---|---|---|
| `startup` | 启动层，盖住整个窗口 | 是 |
| `page` | 侧栏一整页 | 是 |
| `settings` | 设置弹窗里的一块 | 否 |
| `instances.toolbar` | 实例页工具栏 | 否 |
| `account.before-list` | 账号列表上方 | 否 |

`startup` 的特殊之处：

- 只挂**一个**（多个插件都声明时只认加载顺序第一个，其余记警告）
- 在所有页面显示**之前**挂载，`position: fixed` 铺满，`z-index: 5`（低于弹窗的 10，所以崩溃提示能盖住它）
- 插件自己验完、画完之后调 `MLPlugin.dismissStartup()` 收掉
- **只在真启动时挂**：运行中启停插件不会突然盖住用户

### 4.5 宿主事件（4 个）

| 事件 | 时机 | payload |
|---|---|---|
| `instance.created` | 新建实例 | — |
| `launch.preparing` | 点了启动、拿到闸门、正在装配 | `{ instance }` |
| `launch.started` | 进程真的起来了 | `{ instance, versionId }` |
| `launch.exited` | 进程结束 | `{ instance, exitCode }` |

启动动画应该挂在 `launch.preparing`；判断"进游戏了"用 `launch.started`。

### 4.6 启动钩子 vs 启动守卫

```csharp
// 只能加东西
public void OnBeforeLaunch(LaunchRequest request)
{
    request.AddJvmArgument("-Xss4M");
    request.AddGameArgument("--server");
    request.AddGameArgument("mc.example.com");
}

// 能拒绝（参数都装配完之后才问）
public HookResult? OnGuardLaunch(LaunchRequest request)
{
    if (store.IsLocked())
    {
        return HookResult.Deny("启动器已上锁，请先解锁");
    }

    return null;   // 或者 HookResult.Pass
}
```

拒绝的后果：不起进程，界面直接显示「启动失败：被插件拦下：<原因>」。**原因要写人话**，它会被原样显示。

守卫自己抛异常时宿主**会放行**并记日志——不能因为一个插件坏了让用户完全启动不了。

## 5. 下载与安装

插件不要自己 `new HttpClient` 抢带宽，统一走队列：

```csharp
string? taskId = context.Host.Downloads.Submit("下载资源包", [
    new HostDownloadFile("https://example.com/pack.zip", @"D:\...\pack.zip"),
    new HostDownloadFile("https://example.com/pack.sha1", @"D:\...\pack.sha1")
]);

if (taskId is null)
{
    return "队列满了";
}

bool ok = await context.Host.Downloads.WaitAsync(taskId, ct);
HostDownloadStatus? status = context.Host.Downloads.Status(taskId);
```

任务会出现在「下载」页：用户能看进度、能暂停、能限速、能取消。断点续传和 SHA1 校验都是队列做的。

## 6. 权限

| 权限 | 拦截什么 |
|---|---|
| `launch:jvm-args` | 往 JVM 参数里加东西（含 `-javaagent`，所以单独同意） |
| `launch:game-args` | 往游戏参数里加东西 |
| `ui:page` | 挂界面片段 |

**两步都要**：清单里声明 + 用户点同意。缺一步就拒绝：

```
# 没声明 → 直接拒绝挂载
ml.vanilla  ui:page  denied  界面片段未挂载

# 声明了但没同意 → 待确认
ml.vanilla  permissions  consent-required  ui:page
```

审计日志在 `data/logs/plugin-audit.log`。

预留但**不生效**的权限：`network:https` `fs:instance` `account:token`（写进清单不报错，界面上会标"预留"）。

## 7. 还不能做的

| 做不到 | 原因 |
|---|---|
| 否决宿主其它操作（只有启动能否决） | 没有 waterfall 式钩子 |
| 改启动器设置 | `settings.update` 不在契约里 |
| 停用/启用别的插件 | 没有这个 API |
| 定义权限规则 / 做审批流 | 判断逻辑写死在宿主 |
| 拿账号令牌 | `CurrentAccount` 只给 Uuid |
| 读游戏 stdout 流 | 宿主自己接日志，没暴露 |
| 替换宿主页面（首页 / 实例页） | 只能加自己的页 |
| 依赖宿主的 class 名做样式 | 不是契约，见 `04-主题变量.md` |

### 7.1 关于联机 / P2P 打洞

打洞**不需要**宿主提供进程能力，纯插件内就能完成：

| 要做什么 | 用什么 |
|---|---|
| 连信令服务器（云服务器上的那台） | `HttpClient` / `ClientWebSocket` |
| UDP 打洞 | `UdpClient`（BCL 直接可用） |
| 知道用户选了哪个实例、是否在跑 | `Host.Instances[].Running` |
| 让游戏连上打洞后的地址 | `request.AddGameArgument("--server")` + `("127.0.0.1:25566")` |
| 显示房间 / 好友列表 | `page` 插槽 |
| 游戏起来后显示"已连接" | `launch.started` 事件 |

要注意的是 `network:https` 那条预留权限**不拦任何东西**：写不写都能联网，
它只是清单里的一行声明，给用户看"这个插件要联网"。

**唯一的限制**：插件和启动器同进程，关掉启动器房间就散了。
这是刻意的——启动器是壳，关掉壳，壳里的东西就该没了。

### 7.2 开服这类插件怎么写

**宿主不做进程包装**，起/收/发/停都是标准 BCL。宿主只补一件事：你崩了之后谁去杀。

```csharp
// 1) 起进程（工作目录、jar、内存参数全由你决定）
var info = new ProcessStartInfo(javaPath)
{
    WorkingDirectory = serverDir,
    UseShellExecute = false,
    CreateNoWindow = true,
    RedirectStandardOutput = true,
    RedirectStandardError = true,
    RedirectStandardInput = true
};

foreach (var arg in new[] { "-Xmx2G", "-jar", "server.jar", "nogui" })
{
    info.ArgumentList.Add(arg);
}

var server = Process.Start(info)!;

// 2) 这一行是关键：交给宿主托管
//    启动器正常退出、崩溃、被任务管理器结束 —— 服务器都会跟着死
var adopted = context.Host.AdoptProcess(server.Id);

// 3) 输出自己接（一行一个 DataReceived）
server.OutputDataReceived += (_, e) => { if (e.Data is not null) EmitConsole(e.Data); };
server.BeginOutputReadLine();

// 4) 发命令
server.StandardInput.WriteLine("say 你好");
server.StandardInput.Flush();

// 5) 优雅停止：先发 stop，等它自己退；超时再 Kill
server.StandardInput.WriteLine("stop");

if (!server.WaitForExit(15_000))
{
    server.Kill(entireProcessTree: true);
}
```

`AdoptProcess` 返回 `false` 不影响进程继续跑，只是失去了"死也一起死"的保证（可能进程已经退了，
或者平台不支持）。建议在日志里记一条。

**目录**：`context.Host.ServerRoot` 是一个建议位置（`data/servers/`，宿主已创建）。
用不用随你——服务端 jar、`server.properties`、`eula.txt`、`world/` 放哪，宿主不检查也不接管。

## 8. 还没做的（路线图）

| # | 缺什么 | 量级 | 解锁 |
|---|---|---|---|
| 1 | ~~受控子进程~~ **已做最小版**：插件用标准 `Process` 自己起，`Host.AdoptProcess(pid)` 交给宿主托管（见 §7.2） | 小 | 开服插件的进程不会变成孤儿 |
| 2 | 协议号数据源（`HostVersion.Protocol` 现在恒为 null） | 小 | 联机插件判断版本匹配 |
| 3 | 更多可拦截的钩子点 | 中 | 更细的策略类插件 |
| 4 | 皮肤 API（现在只能覆盖 CSS 变量） | 小 | 更深的换肤 |
| 5 | 插件市场 / 分发 | 大 | 生态 |

第 1 项是关键：有了它，"开服插件""内置编程（能跑代码）"才成立。

**定位**：子进程随启动器退出一起结束——不做常驻、不做后台服务、不追求"关掉启动器还活着"。
启动器是壳，插件是壳的延伸。宿主也不包装进程管理：起进程、读输出、发命令、停止，
插件用标准 BCL 就够；宿主只补一件插件做不稳的事（见 §7.2）。

**P2P 打洞不在这一项里**：插件自己用 `UdpClient` 打洞、`HttpClient` 连信令、
`AddGameArgument("--server", ...)` 让游戏连上，**现在就能做**。见 §7.1。

## 9. 两个已知的坑

**`HostVersion.Protocol` 恒为 null**

协议号不在 `version.json` 里（实测 1.21.8 的顶层只有 `arguments` / `assetIndex` / `downloads` / `javaVersion` 这些），只在 ping 服务器时出现。字段先留着，等有数据源再填。现在要用，自己维护"版本 → 协议号"映射表。

**热更替不保证干净**

宿主用 collectible `AssemblyLoadContext`，能卸载再加载（改完 dll 点"重新扫描"就生效，不用重启）。但：

- `Unload()` 只是"请求"，真正回收等 GC（宿主会主动催两轮）
- 插件自己起的线程、注册的全局事件、往宿主静态里塞的东西，**只有 `ShutdownAsync` 里清掉才干净**

所以文件变过之后，插件页会出现「重启启动器」提示（可在设置里关掉）。

## 10. 调试技巧

| 想看什么 | 看哪 |
|---|---|
| 插件为什么没加载 | `data/logs/plugin-audit.log`（`denied` / `consent-required` / `error`） |
| 插件列表状态 | 插件页；`state` 有 `enabled` / `disabled` / `needs-consent` / `error` / `invalid` / `rejected` |
| 崩溃 | `data/crash/crash-*.json`，或用崩溃恢复对话框导出 |
| 页面脚本报错 | 插件页状态栏会写「插件 xxx 的界面脚本出错」 |

## 11. 契约变更策略

- **只加不改**：已有成员的方法签名不改，新能力开新接口（`ILaunchGuard` 就是这么来的，没有去改 `ILaunchHook`）
- 加成员要升 `apiVersion` 的次版本；主版本不同时加载会被拒绝
- 清单字段只加不删（`icon`、`ui:startup` 都是后加的）

插件方：`apiVersion` 写你编译时用的版本，宿主主版本相同且次版本不低于你就能跑。
